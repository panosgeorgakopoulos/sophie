# RAG audit evidence — 21 October 2026

This is an audit artifact, not a production change. All examples below are synthetic. The probes run the actual TypeScript chunking, section mapping, retrieval, validation, system prompt, and chat route through an in-memory transpiler with explicit dependency mocks. They do not read environment secrets or connect to a database, Gemini, SMTP, or the network. A mocked model response proves that application validation is absent; it does **not** establish that a live model was successfully jailbroken.

Run from the repository root:

```sh
node docs/audit-2026-10-21/rag-probes.cjs
```

Result: exit 0; all assertions reproduced the defects described below.

## Reproduced behavior

1. **Email text is silently destroyed in a long paragraph.** A 424-word French fixture containing `Contact: library@example.invalid` produces no chunk containing the email or `Contact:` label. The second chunk begins `Département bibliothèque. invalid information ...`. [src/lib/chunking.ts:15](</Users/panosgeorgakopoulos/Downloads/sophie/src/lib/chunking.ts:15>) uses a regex that cannot span an interior period unless followed by whitespace/end; regex scanning then resumes after the period. This path runs for paragraphs over the 400-word limit at lines 47–55. Dotted emails, URLs, and decimal values are vulnerable to the same class of parsing failure. The fixture demonstrates email loss specifically.
2. **Department identity is lost before a contact block.** A department heading followed by 395 filler words and an email/phone paragraph yields a 397-word first chunk with the heading but no email, then a 56-word second chunk with the email but no heading. `chunkText` carries only the last 50 words (lines 72–80), without a heading hierarchy. The production ingester stores page title and broad category (lines 187–190), not a per-chunk heading path. The context builder only renders a heading if `metadata.section_heading` exists (`retrieval.ts:95–96`).
3. **French page paths are not assigned a section.** `https://www.ifg.gr/eksetaseis/` maps to `eksetaseis`; `https://www.ifg.gr/fr/examens/` maps to `undefined`. This is a string-mapping probe, not a network fetch. A category-filtered SQL query therefore excludes such a French document. Local ingested files likewise receive no `section` field.
4. **Follow-up retrieval drops conversational intent.** The route embeds only `Et son numéro ?`, despite prior history identifying an exam department. This confirms `chat/route.ts:64` does not resolve the subject using history before retrieval.
5. **Client-supplied assistant history is trusted as model output.** The request contains a synthetic prior assistant phone claim; `chat/route.ts:74–82` forwards it unchanged using role `model`. The actual Zod validation accepts this request. No server record is used to authenticate the previous assistant turn.
6. **An unsupported phone is returned with a plausible source chip.** A synthetic retrieved document says only `The library offers books.` and has similarity 0.60. The mocked model returns `Library direct phone: +30 210 0000000`. The route returns that text unchanged plus the fixture library URL. The generation context contains no phone. This proves there is no application check that critical entities are present in the evidence, belong to the requested department, or are supported by the attached sources. It also proves a merely related chunk is treated as sufficient context.

## Architecture observations

- [src/lib/gemini.ts:25–26,65–68](</Users/panosgeorgakopoulos/Downloads/sophie/src/lib/gemini.ts:25>) configures no generation limits/timeout or explicit retrieval query/document task options. `withGeminiRetry` at lines 46–59 only retries rate limits with deterministic backoff and no jitter; provider-default behavior and quota usage should be explicitly controlled. Embedding task configuration must be verified against the actual model/API documentation before changing it.
- The draft endpoint orders raw vectors by L2 distance at [src/app/api/draft-email/route.ts:55](</Users/panosgeorgakopoulos/Downloads/sophie/src/app/api/draft-email/route.ts:55>); the index is on a `halfvec` cosine expression ([schema.sql:47–48](</Users/panosgeorgakopoulos/Downloads/sophie/schema.sql:47>)). Its query cannot use that ANN index and differs from chat retrieval. The webhook also bypasses the indexed expression ([src/app/api/webhook/google-form/route.ts:45–50](</Users/panosgeorgakopoulos/Downloads/sophie/src/app/api/webhook/google-form/route.ts:45>)).
- Chat logging records the message and answer but not retrieved chunk IDs, scores, source versions, model/prompt versions, or the reason a generated answer was accepted ([src/app/api/chat/route.ts:90–93](</Users/panosgeorgakopoulos/Downloads/sophie/src/app/api/chat/route.ts:90>)). Only zero-context cases are flagged (`:99–115`), so wrong answers with a semantically related chunk are not automatically reviewed.
- The no-context language heuristic recognizes Greek script and a short set of French words/accents ([src/app/api/chat/route.ts:18–23](</Users/panosgeorgakopoulos/Downloads/sophie/src/app/api/chat/route.ts:18>)). For example, an accent-free French fragment not matching that list defaults to English; chat history is ignored in this branch.
