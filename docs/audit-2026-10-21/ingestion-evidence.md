# Ingestion audit evidence — 21 October 2026

These are source-level findings plus read-only parser fixtures and public IFG GET requests. No application ingestion, configured database, Gemini request, SMTP operation, or deployment was run. Local document text and filenames are deliberately not reproduced. The companion [ingestion-probes.cjs](</Users/panosgeorgakopoulos/Downloads/sophie/docs/audit-2026-10-21/ingestion-probes.cjs>) extracts only pure functions from the current source; it does not import the ingestion entry point or load environment files.

## High-impact findings

1. **PDF support is absent from the running pipeline.** [src/scripts/run_ingestion.ts:308–311](</Users/panosgeorgakopoulos/Downloads/sophie/src/scripts/run_ingestion.ts:308>) comments out `ingestPDFs`. `ingestWebsitePage` (`166–194`) treats every candidate as HTML; `ingestWebsite` (`197–215`) only visits sitemap entries and never discovers linked documents. The [live exam-registration page](https://www.ifg.gr/eksetaseis/dino-eksetaseis-2/) had eight linked PDFs on audit: exam calendar, fees, regulations, special cases, December/May timetables, registration procedure, and explanatory letter. Two concrete sources are the [2026–2027 calendar](https://www.ifg.gr/wp-content/uploads/2026/10/Calendrier_2026-2027_site.pdf) and [2026 fees](https://www.ifg.gr/wp-content/uploads/2026/01/Tarifs_examens_2026_GR.pdf). The local dataset contains 5 PDF files, 5 DOCX files, 2 Markdown files, and 1 XLSX file. All five PDFs are skipped by normal ingestion.

2. **Enabling the existing PDF function would still miss image-based documents and discard table provenance.** `run_ingestion.ts:226–232` uses only `pdfParse(...).text`, with no OCR, page references, bounding boxes, table reconstruction, or minimum extraction quality checks. Installed `require('pdf-parse')` is callable; all five PDFs returned parse results. One two-page file returned only four whitespace characters (zero trimmed characters); another two-page file returned 89 characters/11 words. This shows a real extraction-quality gap, not a demonstrated defect in `pdf-parse`'s export. An empty parse produces `[]`, and `upsertDocumentChunks:148–157` then deletes previously indexed content and commits no replacement if this function is enabled. DOCX raw-text extraction (`248–250`) and XLSX CSV concatenation (`266–272`) also lack section/table provenance.

3. **The HTML extractor removes contacts and the labels that bind facts to departments.** `run_ingestion.ts:123–136` selects only headings, paragraphs, list items, cells, and blockquotes, drops all `href` attributes, ignores standalone `div` text and `th`, and double-reads nested matching nodes. A fixture `<td><p>DELF A1</p></td>` produces two copies of `DELF A1`; table headers `Diploma/Price`, a div-only phone number, and a `mailto:` address all disappear. It strips Cloudflare placeholders (`116,130`) without decoding `data-cfemail`. On the live [exam-registration page](https://www.ifg.gr/eksetaseis/dino-eksetaseis-2/), three encoded email elements became zero extracted emails. On both exam landing pages, the actual extractor retained only title, street address, and phone, losing the department label and other standalone text. HTML already present inside tabs can be read if it matches the selected elements; JavaScript/AJAX-only content cannot be, because no JS is executed or endpoint traversed. No claim is made that all current IFG tabs require JS.

4. **Category filters exclude every internal document and French category pages.** `run_ingestion.ts:232,250,272,290` records only `document_title` for local files, while `retrieval.ts:52–58` requires exact `metadata.section` for any selected category. No local document can satisfy a category-filtered query. `sectionMapping.ts:8–14` recognizes only Greek root slugs; the real [French exam landing page](https://www.ifg.gr/fr/examens/) returns no section, whereas `/eksetaseis/` returns `eksetaseis`. French equivalents are therefore also excluded in the corresponding category. Remedy: explicit ingest manifest with canonical department, language, audience, source priority, validity and owner; map translated URL families/hreflang to the same department.

5. **Deleted, withdrawn, expired, and renamed sources remain active indefinitely.** `upsertDocumentChunks:148` deletes only an exact source that is successfully reprocessed. A 404/410 (`170–173`), an empty webpage (`180–182`), a now-stale news item (`204–206`), a removed sitemap URL, or a deleted/renamed local file is never retired. `lastmod` is used only for `/news/` age (`97–107`) and is not stored. Schema [schema.sql:5–12](</Users/panosgeorgakopoulos/Downloads/sophie/schema.sql:5>) has no active/version/validity/source-hash columns; retrieval has no freshness condition. Thus rerunning cannot ensure current schedules, regulations, fees, or contact values. Reconcile a completed crawl's source manifest; quarantine removed/withdrawn sources with controlled retry policy; store publication/effective/expiry dates separately from fetch timestamps.

6. **No deduplication, canonical identity, or source precedence exists.** Replacement is keyed only by exact `source_name` (`148`), files use their bare filename, and there is no source type/path/content-hash uniqueness ([schema.sql:5–12](</Users/panosgeorgakopoulos/Downloads/sophie/schema.sql:5>)). This does not deduplicate duplicate files, URL aliases or translated material; filenames from different dataset directories can overwrite each other. No approval/status/priority/version fields are consulted in `retrieval.ts:52–78`. Local redacted analysis found that the large Markdown source repeats substantial 12-word windows from each of the five DOCX files (315 to 3,339 matching windows per pair), so duplicate content is present in the input dataset. Similarity-only top-six retrieval can overrepresent repeated text and has no deterministic way to resolve conflicting internal/web policies. Do not automatically prioritize every internal file; require approved precedence and effective dates.

## Architecture and operational findings

- **Long database transactions around external work:** `run_ingestion.ts:145–157` opens a connection/transaction, deletes source rows, then calls Gemini and sleeps 4.5 seconds for every chunk before committing. The built-in delay alone caps ingestion at 800 chunks/hour; 1,000 chunks consume at least 75 minutes plus network/retry time. Even unchanged sources are re-embedded because no content hash/ETag checkpoint is compared. Holding a transaction/row locks during quota retries increases lock/vacuum pressure and overlapping runs have no per-source lock or uniqueness constraint. Prepare embeddings outside the transaction, stage them, and perform a short atomic version switch with a per-source lock.
- **Crawler has no network or document processing budgets:** sitemap fetch (`63–64`) does not check HTTP status; page fetch (`169–174`) has no deadline/content-type/byte cap. Sitemap recursion (`66–77`) has no depth/visited-set, URL domain validation or redirect checking. A cycle can recurse until failure, a hanging endpoint can block the serial run, and an administrator-supplied or compromised sitemap can fetch arbitrary reachable URLs. This is an offline ingestion trust-boundary issue; there is no public upload endpoint in the inspected source. Add allowed-domain/redirect validation, private-IP rejection, deadlines, size/page-count/depth limits and a deduplicated work queue.
- **The process reports success after partial failures:** `ingestWebsitePage:192–194`, PDF `234–236`, DOCX `252–254`, XLSX `274–276`, and MD `292–294` catch/log per-source errors; `main:322` still prints success. There is no failure tally, manifest, retry queue, run record or threshold for nonzero exit. Missing dataset directories silently return (`219,241,259,281`). Coverage cannot be monitored from the process status.
- **The dashboard's freshness label is ingestion time:** [src/app/admin/(protected)/documents/page.tsx:18](</Users/panosgeorgakopoulos/Downloads/sophie/src/app/admin/(protected)/documents/page.tsx:18>) uses `max(created_at)` as `last_updated`; it does not report source modification time, successful verification time, active version, excluded/failed documents or parsing confidence. `29–30` states every listed source can be answered from, which is stronger than the recorded evidence.
- **Local upload workflow is not implemented:** the admin documents page is read-only (`11–71`) and tells staff to rerun the CLI (`29–30`). All local readers are non-recursive directory scans. This is an operational capability gap, not an unauthenticated upload endpoint.

## Contact and chunking probe

The default 400-word/50-overlap chunker produces a first chunk with `EXAM DEPARTMENT` and no email; the second has the exam email without its department and the library department/email. `chunking.ts:72–80` carries only trailing words; `run_ingestion.ts:187–190` stores only page title/category and never a heading path. `retrieval.ts:95` can render `section_heading`, but ingestion never sets it. The RAG audit separately covers the sentence regex's corruption of email/URL/decimal text.

The hardcoded general fallback contacts were checked: `contact@ifg.gr` is present after decoding the official page's public `data-cfemail`, and `210 339 8600` appears on the [IFG contact page](https://www.ifg.gr/epikoinoniste-mazi-mas/). They were not found incorrect. The issue is lack of managed, versioned verification and specific department binding, rather than observed wrong fallback values.
